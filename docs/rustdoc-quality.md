# Rustdoc quality lane

Status: **pilot, non-blocking** (package 13). This document is the expansion
policy for progressively raising rustdoc quality across the workspace without
making it a dependency of the man/protocol/corpus delivery pipeline.

## Purpose

hyprstream's durable documentation artifacts (man pages, protocol docs,
standards corpus) are generated by their own packages and have their own gates.
Rustdoc is a separate, reviewer-facing quality signal: what the public Rust API
says about itself. This lane makes that signal visible and improvable without
adding a precondition to any other package.

Two invariants hold for the whole lane:

1. **rustdoc generation failures are failures.** A crate whose docs cannot be
   generated (broken build, broken doctests) fails, in CI and locally.
2. **Documentation warnings are non-blocking.** Missing docs, broken intra-doc
   links and similar rustdoc warnings are evidence, not gates. They never block
   a merge while this document says non-blocking, and they must never be
   suppressed wholesale (no blanket `allow(missing_docs)`, no workspace-wide
   `-D warnings` flip) to manufacture a green state.

## Pilot scope: `hyprstream-util`

The pilot crate is `hyprstream-util` — a dependency-light leaf (Apache-2.0,
`parking_lot` only) whose public API is small enough to document to completion.

The lint is enabled **crate-scoped**, not workspace-wide:

```rust
// crates/hyprstream-util/src/lib.rs
#![warn(missing_docs)]
```

It is deliberately *not* added to `[workspace.lints]` in the root `Cargo.toml`:
the workspace lints table applies to every crate that sets
`[lints] workspace = true`, which would be a workspace-wide rollout — out of
scope for the pilot. Each crate opts in individually after measuring its own
baseline.

## Measuring locally

All local Cargo commands run through the fleet BuildQ wrapper (one shared slot,
per the BuildQ policy encoded in the repository's git hooks), via the
`hyprstream-build` helper:

```bash
# Scoped doc generation: warnings visible, generation errors fail.
"$HYPRSTREAM_BUILD" run -- cargo doc -p hyprstream-util --no-deps

# Strict mode: turns warnings into a non-zero exit, for evidence only.
"$HYPRSTREAM_BUILD" run -- env RUSTDOCFLAGS="-D warnings" cargo doc -p hyprstream-util --no-deps

# Doctests for documented examples.
"$HYPRSTREAM_BUILD" run -- cargo test -p hyprstream-util --doc
```

(`"$HYPRSTREAM_BUILD"` is the `hyprstream-build.sh` helper from the build
skills; never invoke `cargo` directly and never set a private
`CARGO_TARGET_DIR`.)

Note that BuildQ enforces a shared-target size floor and refuses with a
retryable error when the pool target is over it; a local measurement blocked
that way is an environment condition, not a documentation result. The CI job
below is the authoritative, always-runnable measurement.

## CI evidence

`.github/workflows/rustdoc.yml` runs the same scoped commands on PRs touching
the pilot (plus manual dispatch) and uploads:

- `rustdoc-hyprstream-util-warnings` — the strict-mode log, showing any
  remaining missing-doc warnings verbatim; and
- `rustdoc-hyprstream-util-html` — the generated API pages.

These artifacts are **quality-review evidence only**. They are not the durable
protocol/corpus/man artifacts produced by other packages, are not consumed by
any downstream job, and carry no release meaning. The workflow is path-scoped
and non-required, so it cannot gate another package's dispatch.

## Expansion policy (adding a crate to the lane)

For each additional crate, in this order:

1. **Measure the baseline** — run the scoped `cargo doc` (locally through
   BuildQ when the queue is healthy, or rely on the CI evidence job) and count
   missing-doc warnings. Record the count in the PR that expands the lane.
2. **Document, don't suppress** — add useful descriptions and examples to the
   public items. Avoid broad `allow(missing_docs)`; a targeted attribute on a
   generated or foreign-shaped item is acceptable when there is no better
   owner for the doc.
3. **Opt in** — add `#![warn(missing_docs)]` to that crate's lib root only.
4. **Extend the evidence job** — add the crate to
   `.github/workflows/rustdoc.yml`'s scoped `cargo doc` invocation (keep
   `--no-deps`; one scoped invocation per crate keeps failures attributable).

Crates with heavyweight build requirements (libtorch backends, feature-gated
modules) are added last, with their applicable feature set, so the evidence job
stays fast and honest. Workspace-wide rollout and any promotion of warnings to
blocking are separate decisions, taken explicitly — never by accretion.

## Out of scope

- docs.rs / registry publication assumptions (the workspace is not published).
- Any change to the man/CLI, protocol, or standards-corpus generation gates.
- The dynamic-CLI caveat stands: runtime MethodMeta lacks the response graph
  needed for protocol docs, so rustdoc coverage of a crate implies nothing
  about CLI/MCP/TS/VFS exposure parity.
