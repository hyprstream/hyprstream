# Documentation pipeline contract

`docs/system-ontology.md` is the authoritative vocabulary and machine-readable ontology. This contract and every generated projection consume it; none may redefine a canonical noun, action, identity, or path.

## Version 1 inputs and outputs

`docs/schema-catalog.json` is the complete, fail-closed inventory of every tracked Cap'n Proto source. It records the file identity, owning package and source license, whether it is a service/type/annotation/protocol/test fixture, CGR producer, and deliberately different consumer surfaces. A surface state is `active` only when a repository source registers it. `declared` means a future/package contract exists; `absent` means no active source is present. A schema that is compiled or has CGR is not thereby a CLI, MCP, VFS, or TypeScript API.

The API manifest is JSON version 1. Entries use stable IDs `api:{service}:{scope}:{method}`, stable paths `api/v1/{service}/{scope}/{method}.json`, canonical UTF-8 JSON, SHA-256 integrity, and a 1 MiB entry limit. `{scope}` is the hyphen-joined scoped-client path from the service root (the service itself at the root), keeping operations such as the per-scope `list` and `status` of the worker API unique. The complete corpus manifest uses `doc:{repository-relative-path}`, paths `corpus/v1/{document_id}.md`, SHA-256 of source bytes, and a 2 MiB document limit. Both manifests carry an audit revision, an independently checked source-tree ID, and a digest over the selected audited inputs, plus exact SPDX license, provenance, size, and digest. The source tree and input digest—not commit ancestry—are authoritative: this permits merge, squash, and rebase integration while rejecting a missing, stale, self-referential, or mismatched input state.

`docs/corpus-sources.json` is the public-prose allowlist. It intentionally excludes coordination state, secrets, unpublished plans, editor state, generated/release outputs, and separately licensed RFC renderings. A new source path is not publishable until it is classified with provenance and license review.

The future `@hyprstream/docs` package is `declared-not-yet-published`: it will export the validated manifest, versioned API entries, and corpus entries only. It must preserve provenance and source license notices and must not copy generated content into a different license boundary. The permissive `hyprstream-docs`, VFS, RPC, and codegen paths remain separated from AGPL application integration as required by `.github/license-boundary.toml`.

## Verification

Run `python3 tools/check-docs-catalog.py`. The checker asks Git for tracked `.capnp` files, so a new schema and a stale removed schema both fail. It derives every schema owner from an audited owner directory and that directory's Cargo manifest, distinguishes persisted-CGR producers from capnp-only test compilation, and compares a normalized, comment/string-free build-script invocation inventory with declared source roots, imports, and schema lists. It compares the catalog to actual CLI builders (both the service and scoped builders, including the deliberately restricted manual `discovery ping` registration), MCP registrations, factory attributes (feature gates plus each factory's declared schema and metadata bindings), VFS dispatch registrations (bound to their generated modules and dispatch types), schema-derived hidden/streaming method inventories using the generator's top-level and scoped response-pairing rules, and tracked TS/JS sources (import/require dependency syntax, including template-literal specifiers). Provenance binds a trusted PR-base or push-before event boundary to the selected source tree and input digest; it does not require the recorded revision to survive squash or rebase. The digest covers every selected public-corpus document (including top-level `docs/*.md`), schemas, build scripts, consumer sources, ownership manifests, and license policy. It rejects duplicate source IDs or service identities, omitted exclusion reasons, widened public-prose patterns, non-SPDX publication licenses, package-policy drift, a stale or self-referential provenance pair, and a catalog that stops naming the ontology as authority.

The attested input digest covers the landing tree, not merely the authoring branch: when `main`'s attested-path universe drifts after an attestation (a new or changed audited input merged on main), the checker fails closed at landing by design. The refresh policy is to merge current `main` into the branch (or merge the branch into `main`) and re-attest the manifests against the merged landing tree before merging; a landing commit may never attest itself.

The consumer sets are intentionally not equal: CLI omits hidden and streaming methods at runtime; MCP has its own registration and policy boundary; VFS has dispatch registrations rather than a promise that every service is mounted; and TypeScript has no tracked package at the pinned base. Update source and catalog together, then run the checker and its mutation probes with `python3 tools/check-docs-catalog.py --self-test`.
